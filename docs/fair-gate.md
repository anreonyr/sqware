## 1 · 卡在哪（有读数）

真机量过：**持树者是串行的**，一台客人连打上千手同步往返，会把别人的期限挤过期。

```text
  probe-deep 最初：512 层 + 512 手剪回来 ≈ 1030 次同步往返
  那一轮 echo 的三手连着 1 秒过期：pname=- trim=7 op=7 seq=1
```

探针后来改成"**每 16 手让一手**"（每层 `room::sleep(1ms)`）⇒ 今天的读数不塌。**性质没有消失**，
只是门里不再由探针制造它。原文的口径（`operator-slot.md` §5.4）写得很清楚：

> 真要收这一格，是**调度/配额**那一族的事，不是树的事。

## 2 · 记录缺口（本门第一条要做的事）

`operator-gate.md` §9 引过一句"那位聊天型客人进 PLAN 的**四次尝试全红**（见 `operator-slot.md` §6）"
——**但 §6 里没有那四次**。故"为什么红"今天**只有结论、没有读数**；而"哪一条读数红了"正是决定
能不能收这一格的把手。**本门第一步就是把它量出来**（不修任何东西，只把红的四条摆出来）。

## 3 · 现成的机器（为什么这一步比看起来便宜）

仓里已经有一条**场景切换**：`SQWARE_ROOT=<名字>` 换的是**引导镜像**，由此换掉整张装配单：

```text
  SQWARE_ROOT=rig    压测台（受害者 + 台主）    scripts/stress.sh
  SQWARE_ROOT=load   忙机台（占核者 + 台主）    scripts/load.sh
  SQWARE_ROOT=group  共享组台（等待者 + 台主）  scripts/group.sh
```

⇒ "聊天客人 + 受害者 + 各自读数"可以是**第四台**：`SQWARE_ROOT=fair` + `scripts/fair.sh`，
**默认装配单一行不动**（前四次全红多半就栽在这里：往默认装配单里塞探针，就动了既有的读数）。

## 4 · 要你拍板的四个点

### 4.1 量什么（"公平"的判据）

| | 判据 | 读数从哪来 |
|---|---|---|
| **甲** | **别人的期限还在一秒内**：有人在猛打时，受害者的同步往返仍然成功（不出现 `pname=- trim=7 op=7 seq=1` 那种过期） | 受害者用既有的 `echo` 那一族读数（`list` / `name` / `trim`） |
| 乙 | **轮转看得见**：每 N 手轮到谁（谁先谁后有账） | 需要**新读数**（持树者自报"这一手是谁的"） |
| 丙 | 只要**不塌**（整机照样停机、既有八道门照绿） | 不需要新读数 |

### 4.2 在哪量

| | 落点 | 代价 |
|---|---|---|
| **甲** | 新场景台 `SQWARE_ROOT=fair` + `scripts/fair.sh`（照 `stress.sh` 的样子，一条命令） | 一台新的引导镜像 + 一位客人（约两小时） |
| 乙 | 放进默认装配单（老路） | **四次全红**——除非先把"为什么红"量清楚 |
| 丙 | 宿主台上量 | **量不了**：串行是机器上那台持树者的性质，宿主靶没有那台机器 |

### 4.3 修不修，修法是什么（读数成立之后再定，也可以先只立读数）

| | 修法 | 代价 / 风险 |
|---|---|---|
| **甲** | **让手**：持树者每服务完一手让一次（`kick` / 让出这一轮），别的客人就能插进来 | 最小改动；会**改变既有读数**（时序类），故得在默认装配单上重新量一遍 |
| 乙 | **配额**：每位客人每轮最多服务 k 手，超了就轮到下一位 | 要引入"客人"这个概念到持树者里（它今天只认孔与号） |
| 丙 | **不修**，把这一格写成"已知边界 + 读数" | 零改动；今天没有真客人要它（与 §9"缺客人的机制"同调） |

### 4.4 改的是谁（这决定门落在哪）

持树者（`programs/src/supervisor/operator/server.rs`）还是调度（`kernel`）？"让手"住在持树者那一侧
（它自己知道服务完了一手）；"配额"两边都碰得到；而**公平**这件事本身属于调度那一族的词。

## 5 · 悬而未决

3. 若修：**让手 / 配额 / 不修**（我推荐先立读数，修法下一刀再裁——因为修法会动既有时序读数）。

## 6 · 我推荐的顺序（认了就这么走）

```text
  一、把四次红量出来（不修任何东西）：fair 台 + 聊天客人 + 受害者，先量"红了哪几条读数"
  二、若那几条读数确实指向"别人的期限被挤" ⇒ 立一台门：scripts/fair.sh（照 stress.sh 的样子）
  三、修法单独再裁一刀（让手 / 配额）——因为修法会动默认装配单上的既有时序读数
  四、若不修：把这一格写进 §9 的"已决的边界"（带读数），清单同样闭合
```
