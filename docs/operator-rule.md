## 0. 一句话

**上一刀问的是"你有没有身份"，这一刀问的是"这一格许不许你"。**

两轴从此分家，各占各的格：

| 轴 | 问的是什么 | 住哪 | 谁判 |
|---|---|---|---|
| **用** | 这一格**谁许用** | 那一格的账上（`Rule<P, C>`） | `find` |
| **改** | 这一格**归谁改** | 同一本账的 `owner` 那一格 | `land` / `trim` |

混成一格就会得出"能改的人自然能用"——而反过来（能用的改不了）才是常见的那一种。

## 1. 功能模型：操作清单

**甲组 · 声明**（今天 5 件，其中 2 件今天不存在）

| 操作 | 今天 | 这一刀 |
|---|---|---|
| `land` 落牌 | `at, name, entry, rule` | **多一格**（用那一轴的规矩） |
| `land` 再来一次 = 换绑 | 有 | 有（`mine = false` 即**放弃归属**，这是新语义） |
| **只改规矩** | **藏在上一条里** | 同左（不新开动作） |
| `trim` 剪掉一格 | 有 | 有 |
| **读回这一格的规矩** | **没有** | **仍然没有**（开了就是新一族，见 §6） |

**乙组 · 用**：`seek`（名→号）/ `find`（号→那一枚，**全族唯一交出权柄的一格**）/ `list` /
`name` / `part`。

**丙组 · 门外那一问的四个落点**

| 落点 | 上一刀 | 这一刀 |
|---|---|---|
| `find` | 只看身份 | **看这一格自己的"用"那一轴** ← 甲的全部内容 |
| `land` | 身份 + 那一格归不归我 | 不变 |
| `trim` | 那一格归不归我 + 身份 | 不变 |
| `part` / `list` / `seek` / `name` | 一律不判 | 一律不判（**读是公开的，写才归属主**） |

**丁组 · 底下那三条边与号的来路**

| 事实 | 上一刀 | 这一刀 |
|---|---|---|
| `resolve(tid)` / `heir(a, b)` | 身份服务（读公开） | 不变 |
| `amid(p, c)` | **持树者手里没有盟册门牌** | **接上了**（各域自己把门牌交给持树者） |
| 规矩里那个号从哪来 | — | 自己的号 / 自己那一支 / 自己在的盟：**问得出**；别人的号：**今天没有发现路**（§6）→ **§7 收了**：多一格「开着某一格的那位」，格号由 `seek` 换来 |

### 裁决

- [x] **号是绝对的**（不上"相对说法"）：`judge::Rule` 的签名本来就是绝对的，判一格只花一问。

## 2. 结构设计

### 2.1 一条记录，两把钥匙

```text
  land   手里有 (坐标, 名)   ─┐
  find   手里有 号           ─┼─→  同一条 Line
  trim   手里有 号           ─┘
```

真机已经量过一次：第一版**按号记**，而 `land` 那一问手里只有坐标 ⇒ **整道判据被跳过**
（`probe-owner` 顶掉了 `/device/uart` 的牌子，读数 `land=OK id=5`）；改按坐标记之后，
`find` / `trim` 手里又只有号 ⇒ 要补一趟 `container_of`（O(树) 的全树递归）。
**两种寻址打的是同一格**——这一条不写成结构，就会反复在两处各补一次补丁。

### 2.2 账是**缓存**，树才是真相

格子从树上有**三条路**会消失，而树一个字都不知道这本账：

| 路 | 谁干的 |
|---|---|
| `trim` | 客人 |
| `find` 的**惰性剔死** | 持树者自己（那一枚答不出就当场剔掉） |
| `part` **顶掉**一枚 `Tile`（`core.rs` §1.5 那个窄口子） | 客人 |

想把"账 ⊆ 树"当不变量，就得给树装三个回调——而**"树不知道规矩"是已定的边界**。
故换一条：**查的时候对一次真相**（`rule` / `claimable` 收的那个 `fresh` 闭包），对不上就
**顺手销账**。这与仓里已经跑通的两条判据**同一条形状**（`find` 的惰性剔死、`claimable` 的
"主人不在场"）：**不问就不动，问了才发现**。

**顺带收掉一笔**：号不复用、**坐标复用** ⇒ 陈旧只可能撞在坐标那一侧；而"剪掉自己的格子之后
重落同名"从此**不受旧归属约束**（今天不删账 ⇒ 剪掉之后别人仍落不进来）。

### 2.3 不变量写成类型义务

| 义务 | 怎么做进去 |
|---|---|
| 一格一条，两种寻址同一条 | 一条记录带两把钥匙 |
| "没声明过归属"要能表达 | `owner: Option<Owner>`（今天靠"账里没这条"隐式表达） |
| **号的宽度 = 它在自己号空间里的宽度** | `judge::Id = u64`；`Control` 三问一起提宽 |
| 缓存陈旧 ⇒ 答默认 + 销账 | 查法收一个 `fresh`，答 `Rule` / `bool` |
| **记账失败不能悄悄放过** | `grow()` 先行（见 §4.3） |

⚠️ 第三条是这一关挖出的第二笔账：`gate::Control` 的号原是 **`u32`**，而 `PrincipalId` /
`CoalitionId` 在 riscv64 上是 `usize`——`Session::who` 那一处写着 `p.get() as u32`，
一次**静默截断**。号不上帧时看不出来；这一刀号要上帧（8 字节），故一并提宽。

## 3. 原语与命名

**对外那一族七个动作码一个不多**：`LAND` 只**变载荷**（帧尾多一格），"改规矩"就是再 `land`
一次；`SEEK = 7` 之后仍然是空的。

**新增的内部原语**（核心那一侧，五个动词 + 一个键）：

| 原语 | 干什么 |
|---|---|
| `Key::{At(Where, Name), Id(EntryId)}` | **两把钥匙合成一格** |
| `Ledger::rule(key, fresh)` | 这一格谁许用（查不到 ⇒ 公开） |
| `Ledger::claimable(key, who, fresh)` | 这一格归不归他改（没记过 / 就是他 / 主人不在场 / 陈旧 ⇒ 真） |
| `Ledger::grow()` / `write(blank, line)` | 先要位，后记账 |
| `Ledger::drop(id)` | 销一行 |

**命名**：树那一侧的词一个都不动（条目 / `Pane` / `Tile` / 落 / 分 / 寻 / 剪 / 列 / 译号 / 名）。
账那一侧新起一族，与仓里既有的注释逐字对上（`server.rs` 今天就写着"主人**那份账**"）：

```
  Ledger   那本账      Line   账上的一行      Owner  那一行记的主人
  rule ↔ claimable（用 ↔ 改）      write ↔ drop（记 ↔ 销）
```

**三处撞名/漂移一并收**：

1. **两个 `Rule` 从结构上消失**：`call::Rule` 不再是一个类型（"改那一轴"退成 `mine: bool`，
   它本来就只是 0/1），`call.rs` 里写一句 `pub use super::judge::Rule;`——**11 处
   `ocall::Rule::Public` 一个字不用改**。方向也是挑过的：`call.rs` 反向依赖 `judge.rs`，
   而 `gate.rs` 那条"不与 `call.rs` 沾边"的纪律一字不破。
2. `PolicyFace`（上一刀 146 处改名漏掉的别名）→ 去掉，直接用 `PrincipalFace`。
3. `call.rs` 里那句引 `judge::Rule::Published` 的注释——那个变体**早就不存在了**。

### 裁决

- [x] `Ledger` / `Line` / `Owner` 这一族名字。
- [x] `call::Rule` 退成 `mine: bool`。
- [x] `Session` 里那两枚门牌叫 `roster` / `league`。

## 4. 签名

### 4.1 这一关逮到一条**已有签名的错**

```rust
// 上一刀（judge.rs）
pub trait League<C> { fn amid(&self, at: C) -> Result<bool, ()>; }
```

盟册那一问**要两个号**（`coalition::client::Face::amid(p, c)`，线上那一帧也带两格），而
`judge` 手里明明有 `me`（第一步就问出来了），却没往下传。今天它是个恒答"问不到"的桩，所以
这个错**一次没响过**。⇒ `League<P, C>::amid(me, at)`。

### 4.2 核心

```rust
pub type Id = u64;                                     // 号在模型里的宽度
pub trait Control {
    fn has_face(&self) -> bool { true }
    fn who(&self, tid: TaskId) -> Result<Option<Id>, ()>;
    fn heir(&self, a: Id, b: Id) -> Result<bool, ()>;
    fn amid(&self, me: Id, at: Id) -> Result<bool, ()>;   // ← 加一格
}
pub struct Ledger<P, C> { lines: Vec<Line<P, C>>, vested_by: VestedBy }
impl Ledger {
    pub const fn new(vested_by: VestedBy) -> Self;
    pub fn rule(&mut self, key: Key, fresh: impl Fn(EntryId) -> bool) -> Rule<P, C>;
    pub fn claimable(&mut self, key: Key, who: TaskId, fresh: impl Fn(EntryId) -> bool) -> bool;
    pub fn grow(&mut self) -> Result<Blank, Fail>;
    pub fn write(&mut self, blank: Blank, line: Line<P, C>);
    pub fn drop(&mut self, id: EntryId);
}
```

`core.rs` **一字不动**（账不在树里；"那一格还是不是枚 `Tile`"用现成两条读拼出来：
`tree.name(id).is_ok() && tree.list(Where::At(id)).is_err()`）。

### 4.3 为什么 `write` 要一个 `Blank`

`land` 的次序是硬的：

```
先动树后记账  →  记账失败 ⇒ 树改了、账没记上 ⇒ 私名变公名（fail-open）   ✗
先记账后动树  →  记不了（号是 land 答的）                              ✗
先要位 → 动树 → 记账                                                   ✓
```

`Blank` 让"没要位就写"**编不过**。顺带把上一刀记在"甲档坑"里的 `try_reserve` 从"顺手修"
升成**必需品**：前身 `Publishers` 是 fail-soft，而同一个 fail-soft 在两轴上后果不同——
改那一轴记不上只是少一条归属账，**用那一轴记不上是开的**。

### 4.4 线上那一侧：帧 51 → 60（**纯追加**）

```text
[0]      op
[1]      at 标记
[2..10]  at 号
[10..42] 名
[42..50] 入口
[50]     mine          ← 上一刀那一格，**值逐字同义**（Owner=1 / Public=0）
[51]     用那一轴的标记  0=公开 1=就是 2=在其支里 3=在其盟里
[52..60] 号（8 字节 LE）
```

**老帧（51 字节）读不到 51 及以后 ⇒ `Rule::Public`**，与今天逐字同义；标记 ≥4（读不懂）
也按 `Public` 走——**一个陌生的规矩不该把整句问话判成 `BAD`**（§7.5③ 那条兜底的第二次应用）。
`ASK_MAX` 不变（60 < 258）。

### 4.5 服务那一侧

```rust
struct Session { roster: PrincipalFace, league: Option<CoalitionFace> }
```

**协调那一帧仍是 16 字节**：`[0..8] = 那位域自己的号`、`[8..16] = 这一枚是哪一双眼睛`
（`0` = 名册，`1` = 盟册）。后 8 字节上一刀**本来就是保留零**，故这是纯追加；
两枚门牌**分两帧、次序不定**，持树者收到哪一枚补哪一枚。

- 装配者按位递号；**门牌由各域自己交**（`serve_tree` 之后直接 `ship` 给持树者，
  照 `principal` 那条现成的路——装配者转授那一版真机栽在 `coord-ship`）；
- `league: Option` 的理由：**降级是诚实的，不是放行**——盟册门牌不到，只有 `Rule::In` 答
  "判不了"（`UNJUDGED`，可重试）。

**四个落点**（今天三处）与**三个销账点**（`trim` 成功 / `find` 答 `Dead` / `part` 顶掉 `Tile`）。

### 裁决

- [x] 要 `Blank`（先把"先要位"做成类型义务）。
- [x] `mine` 留在第 50 字节、用那一轴纯追加在后。
- [x] `mine = false` 重绑 = **放弃归属**（今天旧记录会永久留着，没有"放弃"这一手）。

## 5. 真机读数（这一刀的判据）

```
probe-rule: tree part=8 made=3 p=16 adopt=1 \
            is=0 under=0 in=0 is_sub=8 under_sub=0 in_sub=8
exit tid=19 note: probe-rule: the three rules held

probe-other: tree is=8 under=8
exit tid=20 note: probe-rule-other: both denied as expected
```

同一台客人（**同一条 TID**）换一位代表，三条判据读出两种答案——这就是"规矩随**身份**走"：

| 格 | 以 `p` | `adopt(q)` 之后 | 读出来的话 |
|---|---|---|---|
| `Is(p)` | `0` | **`8`** | 有身份、但**不是那一位** ⇒ 终态拒 |
| `In(c)` | `0` | **`8`** | 在册、但**不在那枚盟里** ⇒ 终态拒 |
| `Under(p)` | `0` | **`0`** | `q` 仍在 `p` 那一支里 ⇒ **看支不看相等** |
| （另一位客人） | `Is` ⇒ `8`、`Under` ⇒ `8` | —— | 换一台客人也一样不在那一支里 |

**`in=0` 这一格还顺带证了装配**：盟册那枚门牌没到持树者手里的话，`amid` 会答"问不到"，
那一格就是 **`9`（判不了）而不是 `0`**——故这一行同时钉住"规矩通了"和"门也接上了"。

读数已进 `scripts/soak.sh`（10 轮全过）。

## 6. 已知边界（记着，不在这一刀里）

1. ~~**别人那个号的发现路**~~：**已收**（§7 第五格 `Rule::Opens`）——留下来的那一半是
   "**某一位叫什么**"（身份的名字）：`resolve(tid)` 要一个 TID，`bloc(me)` 答"我在哪些盟里"，
   而"某一枚盟叫什么、某一位叫什么"仍然没有发现路。今天能表达的因此是「我这一支」「我在的盟」
   「**就是开着某一格的那位**（格号由 `seek` 换来）」「就是某一位（号由别人告诉）」。
2. **重启即失**：账在服务侧内存里；持树者重启这条账就没了（今天没有重启，退出即关机）。
3. **读那一侧仍公开**：`seek` / `list` / `name` 不判 ⇒ 名字是公开的（这是裁决，不是遗漏）。
4. **`part` 顶掉 `Tile`** 时那一行是"顺手销掉"的：漏了不会答错（`fresh` 兜着），只是账会留
   一条陈的。
5. **账的容量**：`grow` 失败 ⇒ `land` 答 `FULL`（fail-closed）。今天条目规模是几十格。
   **这条有牙**（补记）：`judge` 靶的那台宿主靶换了一个**可关掉的分配器**（线程局部旗帜，
   与 `operator` 靶那一台同一款），`a_ledger_that_cannot_grow_answers_full_and_leaves_nothing_behind`
   钉住三件事——备不下 ⇒ `Err(Full)`、**失败不留半行**、放开之后照样写得进。撤掉 `grow` 里那一行
   `try_reserve` 它**当场 SIGABRT**（实测 `memory allocation of 16 bytes failed`）：fail-soft 的下一步
   是 `write` 往没要到位的 `Vec` 里 push ⇒ `handle_alloc_error`。
6. ~~**`UNJUDGED` 那一格只有宿主台的读数**~~：**已收**（§7.6 那两格）——`Rule::Opens`
   让"判不了"能被**确定性地**量出来（那一号是块 `Pane` / 那一格已经剪掉），真机读数
   `at_pane=9 gone_door=9`。**留下来的是那一条因**：要量"身份服务**不答**"得把整机拆掉
   （`judge` 靶的 `a_mute_identity_service_is_unjudged_not_denied` 仍然是它唯一的读数）。

## 7. 第五格 —— **规矩里那个号从哪来**（`Rule::Opens`）

> §6.1 记着的那一笔。四关各由用户裁决一次，`[x]` = 已定。

### 7.1 功能模型：缺的不是"路"，是**点名**

把当时客人手里**能拿到号的五条路**列全（四条已在真机上跑，一条从没被走过）：

| 路 | 拿到谁的号 | 靠什么可信 | 真机证据 |
|---|---|---|---|
| `resolve(self)` | 自己 | 名册（装配期 `derive(ROOT)` + `bind`） | `probe-rule: p=16` |
| `derive(me)` | 我派生的（**只能向下**） | 谱系写，钥匙 = "正好代表 `me`" | `subject` / `member` 的 `sub` |
| `band(c)` | **盟里所有人的号**（一趟取窗） | 盟册公开读 | `member: band(c0)=n1` |
| `opened_by(门牌)` → `resolve(tid)` | 挂过那一枚门牌的域 | 内核戳"谁开的这扇门" | `probe-rule` 靠它找两面门牌 |
| `collect().vestor` → `resolve(tid)` | 给过我东西的那一位 | 内核戳"谁授的" | `client::take` 那一手 |
| （报文里塞来的号） | 任意 | **零校验** | 今天无一位客人这么写 |

⇒ **"把这一格许给某一位"写得出来，但只有那五种"某一位"指得到**。缺的是一句：
**「许给 `/device/uart` 那位」**——号是纯数，没有任何名字/角色能指到它。

### 7.2 四个形状（连被否项一起）

| | 形状 | 代价 |
|---|---|---|
| **①** | 名册带名字（`principal` 长出一张名录 + 两条公开读） | 仓里从此**两套名字**（树管 Pie、名册管身份），要对齐重名/改名/谁有权命名。好处硬：换载体规矩不变 |
| **②** | **树当名录**（规矩里写**格号**，判的时候现场翻） | 权限跟着**门牌**走（剪掉/顶掉那一格 ⇒ 判不了）；规矩从"值"变成"引用" |
| ③ | 装配单 args（装配者在装配期把"名字 → 号"翻给客人） | 只到装配期；且号是 `derive(ROOT)` 顺序的产物 ⇒ 加一条服务全表错位 |
| ④ | 不造机制（只造一台探针把第五条路走完） | 「许给 `/device/uart` 那位」仍然说不出来 |

**裁决：走 ②**——它是唯一"一个机制同时把那句缺失的话补上"的形状：客人本来就会 `seek`
（名字 → 号），把那个号写进规矩即可，**线上仍是 8 字节**；而"号不重用"是上一刀刚钉死的
（`core.rs`：剔掉不回收号）⇒ 别人顶不了那一格。

**被否的第五个形状**：规矩里直接写**一条路**（名字序列）。名字与挂载解耦，但 ① 线上装不下
（`ASK_MAX = 258`，`land` 帧已用 60，剩 198，而一条路最多 `ROAD_MAX(8) × 32 = 256`；限长度就是
又一个手拍常数——这门里撞满过三次）；② 它违反已定的「**号成唯一直接坐标**」。

### 7.3 结构：规矩里存的是**格号**，不是身份号

```rust
pub enum Rule<P, C> { Public, Is(P), Under(P), In(C), Opens(EntryId) }
```

**晚绑定，与 [`Rule::In`] 同形**（`In` 存一枚盟号、成员现场问；`Opens` 存一个格号、占着它的
那位现场问）。规矩里**没有**解出来的身份号可存——这是结构，不是注释。

判那一格走**两问**：树答"第 `e` 格是谁的门牌"（内核戳，**TID**），名册答"这个 TID 此刻代表谁"
（号）——一件事一个落点。

### 7.4 原语与命名

| 操作 | 原语 | 这一刀 |
|---|---|---|
| 客人**点名**（名字 → 号） | `seek` | **一字不动**（不新开"查名录"这个动作） |
| 客人**声明规矩** | `land` | **动作码不变**，载荷多一个变体 |
| 持树者**判** | `find` 里 `judge` | 内部一支 |
| 持树者**问**"第 `e` 格谁开着" | **`Operator::opens`** | **新**（核心只读，**不上线**） |

`Rule::Opens(e)` ↔ `Operator::opens(e)`：**规矩问的那一句就是树答的那一句**（同一句话的
正反面）。**线上七个动作码一个不多**——第八条没有动作码。

**被否的名字**：`At`（与 `Where::At` 那枚**容器坐标**撞，且会读成"在这一格里"）/
`Held` / `holder` / `holds`（`holder` 在本仓专指**持树者**）/ `Owner`（账里"归谁改"那一格
就叫它）/ `opened_by`（**已经有主**：`operator::call::opened_by` 收的是 `PieToken`）/
`landed_by`（树收到的是 `ship` 来的副本，**"谁落的"与"谁开的"在转授之后不是同一位**）/
`vested_by`（另一个戳子）/ `peek` / `probe` / `look`（**实现细节词**）。

### 7.5 签名

```rust
// core.rs —— 注入的两枚戳子收成**一格具名的组**
pub type OpenedBy = fn(PieToken) -> Option<TaskId>;      // = session::call::opened_by
pub struct Stamps { pub vested_by: VestedBy, pub opened_by: OpenedBy }
pub const fn new(stamps: Stamps, unship: Unship) -> Operator;

/// 树 · 读：**第 `id` 格是谁的门牌**。
/// `Ok(tid)` 活砖的开者；`Unknown` 碑/没铸过；`NotATile` 是块 `Pane`；`Dead` 开者那扇门封印了。
/// **不动树**（不剔死、不销账）、**不交出任何句柄**——与 `find` 正相反。
pub fn opens(&self, id: EntryId) -> Result<TaskId, Fail>;

// judge.rs —— 第五格与它的第四枚事实源
pub trait Door { fn opens(&self, at: EntryId) -> Result<Option<TaskId>, ()>; }
pub fn judge<P, C>(who, rule, roster, branch, league, door: &impl Door) -> Ruling;
```

**两枚戳子收成一格具名的组**的理由：它们**同型**（`fn(PieToken) -> Option<TaskId>`），摆成位置
参数时写反了照样编过——而 `session` 那一族认 `owner` 还是 `grantor` **实测栽过一次**，同族的
坑不再留。

**三因一码**（`Dead`）：不是孔 / 不在我表里 / 已封印——不许拆它，今天没有一位客人分得开。

**`Door` 的 `Ok(None)` 也是三因同落**（碑 / 是块 `Pane` / 门封印）⇒ `Unjudged`（可重试）；
**开者没绑身份** ⇒ `Deny`（与"没身份就是没资格"同一条）。

#### ⚠️ 这一刀破了既有契约的一处，照实记

`judge` 的头注原写"**先问身份、只问一次**"（"顺手再问一次在这里就是双倍成本"）。而晚绑定
**必然要多问一次名册**（问的是另一条 TID：开者）⇒ 契约改成"**先问身份；`Opens` 那一格多问
一次**"，而"第一条闸在谓词之前"**一字不改**。宿主台那条用例名也跟着改了。

### 7.6 真机读数

```
probe-rule: tree part=8 made=3 p=16 adopt=1 is=0 under=0 in=0 \
            is_sub=8 under_sub=0 in_sub=8 door=13 open=0 foreign=8 open_sub=0 \
            trim=1 at_pane=9 gone_door=9
exit tid=19 note: probe-rule: the rules held

probe-other: tree is=8 under=8 foreign=8
exit tid=20 note: probe-rule-other: all three denied as expected
```

| 格 | 规矩 | 谁在问 | 答案 | 读出来的话 |
|---|---|---|---|---|
| `open` | `Opens(door 的号)` | 本域（**门牌正是它开的**） | `0` | 开者能过 |
| `foreign` | `Opens(/sys/principal 的号)` | 本域 | `8` | **"许给某一位"**——号由 `seek` 从树上换来，而那位不是本域 |
| `foreign` | 同上 | **第三台客人** | `8` | 换一台客人也过不去（`probe-other`） |
| `open_sub` | `Opens(door 的号)` | 本域（`adopt(q)` 之后） | **`0`** | 与 `is_sub=8` 对照：`Opens` 比的是"**开者那条 TID 此刻代表谁**"，开者与问的人是同一条 TID ⇒ 两边一起变 ⇒ **规矩随身份走** |
| `at_pane` | `Opens(/sys 那一格)` | 本域 | **`9`** | 那一号是块 `Pane`（**没有开者这一说**）⇒ **判不了**（可重试），不是拒 |
| `gone_door` | `Opens(temp 的旧号)`（`temp` 先落上、再 `trim`） | 本域 | **`9`** | 那一格剪掉了、而**号不重用** ⇒ 永久没有开者 ⇒ 判不了（§7.7 第 1 条那一笔的读数） |
| `keep` | 自己声明归自己的那一格（`mine = true`），**`adopt(q)` 之后**再落一次 | 本域 | **`0`** | 与同一次 `is_sub=8` 并列：**"改"那一轴记的是命**（见 §7.8）——主人换了代表照样改得动自己的格子 |

**末两格是门禁第三格第一次上真机**：`UNJUDGED` 此前只有宿主台的读数（要量"身份服务不答"得把
整机拆掉）。这两条因各不相同（是块 `Pane` / 已剪掉），而判据**只需要"有没有那一位"**——
落 `8`（终态拒）会让客人白放弃，落 `0`（放行）等于门禁不存在。

**`foreign` 那一格为什么不依赖次序**：它指的是一枚**长命**门牌（`/sys/principal`，整轮都活着）。
若改指一位用完就退场的客人，那一格会翻成 `9`（判不了——开者的门封印了）而不是 `8`。

读数已进 `scripts/soak.sh`（10 轮全过）。

### 7.7 已知边界（记着，不在这一刀里）

1. **规矩绑在"一次挂载"上**：号不重用 ⇒ 那一格被剪/被顶之后 `Opens` 那一格**永久判不了**
   （重挂是**新号**）。这是"此刻占着这一格的那位"的题中之义，不是缺陷；要"换载体规矩不变"
   就得给身份起名字（那是形状 ①，今天没有客人要它）。**这一条有读数**：`gone_door=9`
   ——探针把 `temp` 落上、剪掉，再指它那个旧号。
2. **多一次问答**：`Opens` 那一格 = 一次核心本地读（树）+ 一次 envcalls（名册那一问）。
3. **`opens` 不上线**：客人读不到"这一格是谁的"——只有持树者判的时候问。今天没有客人要它。
4. **核心八条、线上七条**：`core.rs` / `operator/mod.rs` / `operator` 靶的口径一并改了
   （先例：`principal::clan` 是"核心有、线上不发"；本条的差别是**它有真客人**——持树者自己）。

### 7.8 顺手裁掉的一条：**归属那一轴跟命，不跟身份**

两轴分家之后一直挂着一个不对称：**用**那一轴论**身份**（`Is` / `Under` / `In` / `Opens` 判的都是
"这一位此刻代表谁"），而**改**那一轴记的是**命**（账里 `Owner` 那两格 `who` + `pie` 都是任务级的）。
这一刀把它**裁掉**：不改成身份，而是把理由写死——因为它**不是疏忽，是护栏决定的**。

三条理由，一条比一条硬：

1. **键与护栏必须同级**。"改"那一轴唯一的护栏是"**主人还在不在场**"（`vested_by`：那一刻挂上去的
   那一枚还答得出吗），而**封印是按任务来的**（退场钩子封印该域开的资源）。若键改成身份，护栏就
   得问"**那一条身份**还在不在场"——而身份**永不消亡**（`principal` 的节点只增不删，K4）⇒
   那条护栏当场失去意义，"规矩属于活着的**主人**"也就无从谈起。记命 ⇒ 键与护栏同源。
2. **`mine = true` 是一个动作的产物**：它是"**我**落牌那一刻声明这一格归我"——动作的主语是任务。
3. **今天没有客人要那另一种**：借调"另一枚 TID 代表同一条身份也能改"这件事，本仓只有探针自己
   `derive` 出来的子身份（`subject` / `member` 那两台），而它们从不碰别人的格子。

**被否**：把 `Owner.who` 换成 `Id`（身份）。代价两条照实记：① 写那一侧要多问一次名册
（`claimable` 之前得先把发送者换成身份），而**用**那一侧刚刚才为 `Opens` 破过一次"只问一次"；
② 键与护栏不同源（见理由 1）。换来的是"与用那一轴同键"这一条形式上的整齐——不值。

**真机读数**（这一条不是纸上的）：`mine=19 keep=0`——本域先用 `mine = true` 落一格，`adopt(q)`
之后**再用一枚新孔重落它**（换绑），答 `0`（放行）；而同一次 `Is(p)` 那一格答 `8`。
**一条 TID 换一位代表："用"那一轴变了，'改'那一轴不变**——两条轴各问各的问题，各自自洽。

**照实记（这一格原来记在别处）**：`operator-rule.md` §1 的裁决里写着"号是绝对的""两轴分家"，
但那一刀没裁"改"那一轴论什么。这条不对称从 `f4f0da9` 一直挂到现在。

### 7.9 顺手收掉的一条：**问话孔"只可能有一枚"从纪律变成构造**

`operator-gate.md` §8 那张复核表里留着一句"**干净的关法是另一刀**"：让 `ask_hole` 与入口那一枚
也走有名有姓的泊位（`Quay::seat` 那条路已经有同名闸）。这一刀收了它——但取的是**小形状**。

**形状**：客侧 `ask_hole` **先找后铸**——`session::call::find(本端, 记号)` 那一手已经是"按
**两格正判据**（谁开的 + 记号）找我这张表里的那一枚"，有就把它还回来，没有才铸。于是
**同一张表里再也生不出第二枚问话孔**。代价是**零**：签名与二十处调用点一个字没动（若走
`Quay::seat` 那一版，二十处调用点的签名都要跟着改），而两者给的是**同一句保证**——`seat` 的同名闸
在码头那一层，谁绕过 `seat` 自己铸孔也绕得过；这一版把闸装在**那个记号唯一的铸者**身上。

**照实记：这一半"入口那一枚"不成立。** 复核表把 `ASK` 与 `ENTRY` 并列成"契约被破"，而
`find_face` 的头注写着"多枚**正常**（副本共享 `opened_by`：`land` 交一枚、门禁交一枚）"，
`echo` 更是**故意**铸两枚入口（板一枚、树一枚，两个不同的对端）。那一半不是纪律被破，是设计。

**量出来的另一半（这一刀真正的收获）**：两面的问话孔原先刻的是**同一个记号**
（`operator::ASK_MARK` 与 `board::ASK_MARK` 都是 `Mark::of("ask")`）。今天无害，只因两枚孔落进
**两张不同的表**（板线程 / 持树者）。先找后铸一上，它们就落进**铸者那一张表**了 ⇒
`operator::ask_hole` 当场把**板那一枚**当成树那一枚交回来 ⇒ 树那条路永远没有问话孔。
**实测**（真机，负证）：

```

principal / derive self
system: service failed
```

`examine` **0/3**。故这一刀同时把两个记号分开：`operator-ask` / `board-ask`——与两面的
`operator-tip` / `board-tip`（泊位名）和那一族的 `rtc-back` / `principal-back`（回信孔记号）
同一条命名。

**真机读数**（正证，3 次开机一致）：

```

```

`ask_same=1` = 第二次要回来的是**同一枚**；而这一台下面每一问用的**正是第二枚那个号**——
它要是另一枚孔，持树者认的还是第一枚，这些话全石沉大海（`session` 事实 9 那个症状）。
外加 soak 里一条**缺席判据**：全程不许出现 `operator: two asks`。

**边界（记着）**：`claim` 那一句"命中两枚就报一句"**留着**——它是纵深（万一哪天有人绕开
`ask_hole` 直接铸那个记号），而它现在报的那一句是一次**真的**契约被破，不再是那种结构性误报。
